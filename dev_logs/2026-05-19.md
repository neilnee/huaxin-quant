## 下午场：报告模板重构 + 双标的实测

### 报告模板：从流程式到估值模型式

**问题**：原报告按执行流程组织（业务拆解→定价→预期差→催化剂），估值结论埋在第三章。用户需要的是"打开报告第一屏看到答案"。

**新模板结构**：估值总览 → 支柱一/二/三逐个展开（计算逻辑+假设+依据+敏感性）→ 增长曲线 → 催化剂 → 风险。核心原则：**先给答案，再拆公式，再列依据**。

| 改前 | 改后 |
|------|------|
| 一、公司概况 → 二、定价基准 → 三、预期差 → 四、催化剂 → 五、风险 | 一、估值总览 → 二/三/四、逐支柱拆解 → 五、增长曲线 → 六、催化剂 → 七、风险 |
| 估值结论在第 2-3 章 | 估值结论在第一屏 |
| 业务描述和估值计算混在一起 | 每个支柱独立单元：公式→假设表→数据来源→敏感性 |
| 增长预期散落在预期差章节 | 增长曲线单独成章 |

### 分歧度：从散落到固定

分歧度（`(最高-最低)/均值`，衡量分析师预测离散程度）原本是 2.2 的一个检查项，但在实际报告中分散在不同位置（有时在支柱假设表、有时在增长曲线脚注）。**修入模板**：报告头部 + 估值总览两个固定位置。润泽 83.7%（分歧极高）vs 金盘 18.9%（共识良好），两个极端案例验证了指标的区分度。

## 晚间场：估值方法论重构 + 脚本落地 + v1.1 发布

### 触发

复查 v1.0 的两份报告时发现：估值区间来自"加不加某个业务"（保守=支柱一，乐观=支柱一+二+三），而非每个支柱自身的不确定性。这导致保守估值过低、乐观过高，且逻辑不自洽——即使核心主业也有 PE 高低和利润变化，自身就应有区间。

### 估值方法论：从层叠式到情景式

**旧逻辑（层叠式）**：
```
保守 = 只有支柱一
合理 = 支柱一 + 支柱二
上限 = 支柱一 + 支柱二 + 支柱三
```

**新逻辑（情景式）**：
```
每个支柱独立设保守/基准/乐观三情景，按情景加总：
保守估值 = Σ 各支柱保守
基准估值 = Σ 各支柱基准
乐观估值 = Σ 各支柱乐观
```

### 三条通用规则固化

**规则 1：基准的"确定性折扣"** — 支柱确定性越低，基准越不能取完整分析。完整兑现是乐观的事。
- 高确定性（核心主业，3年+已验证）→ 基准 ≈ 100% 完整分析
- 中确定性（有先例但非年度规律）→ 基准 ≈ 70-90%
- 低确定性（远期/早期孵化）→ 基准 ≈ 30-50%

**规则 2：保守情景的"合理悲观"刻度** — 保守是有可能发生的不利情景，不是末日。
- 按确定性分档给出 PE/利润/概率 三个维度的折扣参考区间

**规则 3：PE 倍数取值量化** — 从"拍脑袋"到"三步走"。
- 第 1 步：确定可比 PE 区间
- 第 2 步：增速比调整（增速比 = 公司增速/可比增速，PEG ≤ 1.0 为硬上限）
- 第 3 步：定性溢价/折价因子（每个 ±5-10%，总调整不超 ±20%）

### 确定性上调因子

新增"背书因子"规则：头部客户/合作伙伴明确背书 + 送样/验证里程碑 → 可上调半级（低→低偏中→中），最多半级不可跨级。金盘 SST 受英伟达背书上调至"低偏中"，基准兑现 43%→57%。

### 金盘 vs 润泽：DeepSeek 交叉验证

将金盘报告发给 DeepSeek 评审，三条建议中采纳了两条方法论优化（PE 量化规则、背书因子），一条属于个股判断分歧（基准利润取 9.74 vs 10.5 亿）——恰好验证了三情景设计的合理性（乐观已覆盖 11 亿）。

| 指标 | 金盘 v1.0 | 金盘 v1.1 | 变化原因 |
|------|---------|---------|---------|
| 基准 PE | 40x | 45x | PE 量化规则（PEG=0.94） |
| 基准股价 | 88.04 元 | 99.57 元 | +11.53 元 |
| 乐观 PE | 45x | 50x | 同规则 |
| SST 确定性 | 低 | 低偏中 | 英伟达背书 |
| 折扣率 | 0.88 | 0.79 | 当前价接近基准 |

润泽基本不变——PE 35x 经量化规则验证成立（PEG=0.74），路线 A1 以 EV/EBITDA 为主。

### `valuate.py` 脚本落地

模型三阶段零配套脚本从规划落地为实际代码（27257 字节）。

**核心能力**：
- 扫描 `cache/financial/` 中 mx-data 原始 JSON，按字段名（nameMap）自动提取关键指标
- 计算 11 项衍生指标（OCF/NP、固定资产/总资产、非经常性占比、毛利率 3 年波动等）
- 自动判定决策树五信号（Q1/Q1b/Q2/Q3/Q_IRREG）并分派估值路线
- 自动判定预期差漏斗信号（产能/技术/非经常性，含 HIGH/MEDIUM 优先级）
- 输出结构化简报册 JSON → `cache/briefing/<code>_<YYMMDD>.json`

**踩坑记录**：
- **字段反向匹配**：`kw in field_name or field_name in kw` 导致"归属于母公司股东的净利润"被"扣除非经常性损益后归属于母公司股东的净利润"误命中 → 改为仅 `kw in field_name`
- **多文件覆盖**：`all_data.update(parsed)` 导致小文件（含旧周期数据）覆盖大文件（含最新数据）→ 改为按周期逐字段合并，先加载的优先
- **周期偏好缺失**：lookup 未指定 `prefer_period` → 增加了年报优先排序逻辑

**脚本 vs LLM 分工**：脚本管数值（解析→计算→信号），LLM 管判断（业务拆解→搜索→叙事）。改估值策略只动指令卡，不动脚本；加新财务指标才需改脚本。

### 工程配置
