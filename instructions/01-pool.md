# 模型一：海选初筛模型（自执行指令）

- **版本管理**: 由 Git 分支与提交历史管理，文件名不再携带版本号
- **最近更新**: 2026-07-03
- **核心目标**: 从全市场筛选优质资产，建立候选观察池
- **核心哲学**: 只看"已兑现"的资产历史质量，先让数据说话，再用行业标签做减法
- **输入**: 全市场 A 股 | **输出**: `pool/pool_<YYMMDD>.csv`（候选池，供模型二使用）
- **配套脚本**: `scripts/run_pool.py`（端到端入口） + `scripts/process_pool.py`（阶段二到五处理）

---

## 总览

本任务分 **5 个阶段**，每阶段有明确的输入、输出和操作规范。

```
阶段一（mx-xuangu）→ 阶段二（自算过滤）→ 阶段三（行业排除）→ 阶段四（输出CSV）→ 阶段五（打印摘要）
```

**核心设计原则**:
- API 能算的交给 API（增速、毛利率、研发占比、ST）
- API 算不了的自己算（OCF/NP 比值、上市天数）
- 数据一次拉取，不在中间环节重复调 API
- 市值分段互斥查询，解决 200 条上限；50 亿以下标的直接不进入候选池
- 段数据文件本地缓存（`cache/xuangu/`），同一分段同日只拉一次，后续分析复用缓存
- 脚本与指令同提交更新，历史版本由 Git 追溯

## 阶段一：市值分段拉取初筛池

### 目标
从全市场获取满足 5 项 API 条件的股票，同时拉回全部原始字段供后续阶段使用（行业、估值、财务、上市日期等共 13 个字段）。

**段数据文件即缓存**: 每次 xuangu 调用产出一个 `*_raw.json` 文件到 `cache/xuangu/`。同一分段在同一交易日的结果不变，因此这些文件应**保留复用**而非删除。后续执行时先检查段文件是否已存在且当日生成，命中则跳过该段的 API 调用。

### 查询模板

对每个市值分段，使用 mx-xuangu Skill 查询。**替换 `{市值范围}` 部分**：

```
营收同比增长率大于15% 净利润同比增长率大于20% 毛利率大于15% 研发费用占营收比例大于2.5% 排除ST股 {市值范围} 查询所属行业 上市日期 总市值 市盈率 市净率 ROE 营业收入 每股收益(2025年年报) 经营活动产生的现金流量净额(2025年年报) 归属母公司股东的净利润 资产负债率 A股
```

**字段说明**:

| 查询中的字段 | 用途 | 阶段 |
|-------------|------|------|
| 营收同比增长率 > 15% | API 侧过滤 | — |
| 净利润同比增长率 > 20% | API 侧过滤 | — |
| 毛利率 > 15% | API 侧过滤（**不加年份**，原因见踩坑#3） | — |
| 研发费用占营收比例 > 2.5% | API 侧过滤（**不加年份**，原因见踩坑#7） | — |
| 排除ST股 | API 侧过滤 | — |
| 查询所属行业 | 行业排除 | 三 |
| 上市日期 | 计算上市天数 | 二 |
| 总市值 | 输出字段 | 四 |
| 市盈率 | 输出字段 | 四 |
| 市净率 | 输出字段 | 四 |
| ROE | 输出字段 | 四 |
| 营业收入 | 输出字段（不加年份，xuangu 自动返回多期） | 四 |
| 每股收益(2025年年报) | 输出字段（需年份限定，否则仅有LATEST版） | 四 |
| 经营活动现金流(2025年年报) | 计算 OCF/NP 比值 + 输出（需年份限定，否则仅有LATEST单季度） | 二/四 |
| 归母净利润 | 输出字段（不加年份，xuangu 自动返回多期） | 二/四 |
| 资产负债率 | 判断 < 70% + 输出 | 二/四 |

### 市值分段（4段，互斥）

```
段1: 总市值大于50亿 总市值小于100亿
段2: 总市值大于100亿 总市值小于200亿
段3: 总市值大于200亿 总市值小于500亿
段4: 总市值大于500亿
```

**段边界策略**: 50亿、100亿、200亿、500亿。50 亿以下标的不再拉取；脚本仍会执行 `总市值 >= 50亿` 硬过滤，防止旧缓存或异常字段漏入。若某段仍然 ≥200 条（total 字段显示），对该段再按市盈率正序/倒序拆成两次查询（追加 `按市盈率从小到大` / `按市盈率从大到小`）。

### 执行步骤

0. 使用统一入口执行模型一：
   ```bash
   python3 scripts/run_pool.py
   ```
1. `run_pool.py` 对每个分段先检查 `cache/xuangu/` 目录下是否已有未过期且查询条件完全一致的 `*_raw.json` 文件。命中缓存则跳过 API 调用；需要强制刷新时使用 `--force-refresh`。
2. 缓存缺失时，脚本自动拼接完整查询字符串，并调用 mx-xuangu 本地脚本：
   ```bash
   python3 /Users/neil/.codex/skills/mx-xuangu/mx_xuangu.py --output-dir cache/xuangu --query "{查询字符串}"
   ```
3. 检查返回数据中的 `total` 字段：
   - `total < 200`：本段全覆盖，提取 `dataList` 全部记录
   - `total >= 200`：本段可能截断，自动追加 `按市盈率从小到大` / `按市盈率从大到小` 两个子查询
4. 阶段一完成后，`run_pool.py` 自动调用 `process_pool.py` 进入阶段二到阶段五。
5. `process_pool.py` 以 `SECURITY_CODE`（补零到 6 位）为 key 合并所有有效 raw 数据，去重后继续过滤和输出。

**调用约束**:
- xuangu 调用串行执行，段间间隔 1-2s（避免触发限流）
- 总调用量约 4-8 次（4 段 + 可能的子分段），远低于 500 次/天配额
- 网络错误重试 1 次；API 异常错误检查后决定是否继续
- 段文件写入 `cache/xuangu/`，文件名由 mx-xuangu 自动生成（含查询关键词）

### 预期输出
合并去重后的股票列表（dict/list），每条包含：SECURITY_CODE, SECURITY_SHORT_NAME, 行业字段, 上市日期, 经营现金流, 归母净利润, 资产负债率, 及各增速/比率字段。

### 段数据缓存与脚本复用

**缓存目录**: `cache/xuangu/`（实际为段数据缓存，不是临时文件，**同一天内不删除**）

**缓存策略**:
- xuangu 各段查询结果以 `*_raw.json` 格式存储，文件名含查询关键词
- 同一分段 + 同一查询模板 → 文件被覆盖更新，无需手动清理
- `process_pool.py` 按文件修改时间过滤：**只加载 5 天内的文件**，超期自动跳过并警告
- xuangu 数据以财报指标为主（季度更新），5 天窗口覆盖周度波动，无需每日重拉
- 旧文件不会自动删除（保留调试），LLM 在财报季或怀疑数据过期时手动清空目录重拉

**脚本 CLI**:
```bash
python3 scripts/run_pool.py                 # 默认：阶段一拉取/复用缓存 + 阶段二到五处理
python3 scripts/run_pool.py --force-refresh # 忽略缓存，强制重拉阶段一分段数据
python3 scripts/run_pool.py --skip-fetch    # 只执行阶段二到五，复用已有 cache/xuangu 数据
python3 scripts/run_pool.py --no-process    # 只执行阶段一拉取，不生成 pool CSV
python3 scripts/run_pool.py --dry-run       # 只打印查询和命令，不发起网络请求
python3 scripts/process_pool.py             # 内部处理脚本：从 cache/xuangu/ 读取并输出 CSV
```

**工程约束**:
- 段文件不包含下游计算（过滤逻辑在 process_pool.py 中），筛选规则变更时缓存不受影响
- 段文件损坏或缺失 → 重新调用 xuangu 对应段即可
- 日期跨天后，段文件自动过期（新一天的查询 date 不同，旧文件不被 process_pool.py 匹配）
- 脚本与指令同提交更新，规则变更不再维护文件内版本号

**脚本化状态说明**:
- 已脚本化：阶段一分段查询、缓存复用、截断补充查询、缓存读取、字段匹配、硬过滤、行业排除、CSV 输出、摘要统计。
- 不引入 LLM：阶段一查询条件固定，由脚本模板生成并直接调用 `mx_xuangu.py`，避免依赖对话上下文。
- `process_pool.py` 保持为阶段二到五的纯处理脚本，`run_pool.py` 是模型一端到端调度入口。

## 阶段二：自算过滤

### 目标
对阶段一结果，计算 API 无法完全稳定处理的硬性门槛，并补充软标签供后续模型排序和人工复核。

### 2.1 字段匹配规则

**API 返回的字段 key 是动态生成的**（如 `010000_RPT_..._PARENTNETPROFIT{2025-12-31}`），必须用**模糊匹配**，不能用精确 key。

**核心原则：优先锁定年报；年报字段不完整时，NP/OCF 必须统一降级到同一 `#LATEST#` 周期。**

同一字段可能存在多个版本的 key（如 `{2025-12-31}` 年报 和 `#LATEST#` 最新期）。`#LATEST#` 可能返回季度数据（如 2026Q1），不能与年报字段混用。脚本规则是：若归母净利润和经营现金流都能匹配到年报，则统一使用年报；若任一缺失年报，则两者统一使用 `#LATEST#`，并根据数据周期使用差异化阈值。

匹配规则如下（按优先级排列，命中高优先级即停止）：

| 目标字段 | 匹配方式（按优先级） |
|---------|---------------------|
| 归母净利润 | ① key 含 `PARENTNETPROFIT` **且** 含最新年报报告期；② 与经营现金流一起统一降级到 `#LATEST#` |
| 经营现金流 | ① key 含 `NETOPERATECASHFLOW` **且** 含最新年报报告期；② 与归母净利润一起统一降级到 `#LATEST#` |
| 营业收入(2025年报) | ① key 含 `OPERATEREVE` **且** 含 `2025-12-31` |
| 每股收益(2025年报) | ① key 含 `EPSJB` **且** 含 `2025-12-31`；② key 含 `BASICEPS` **且** 含 `2025-12-31` |
| 资产负债率 | ① key 含 `ZCFZL`；② key 含 `资产负债` 或 `DEBT_ASSET` |
| 上市日期 | ① key 含 `LISTING_DATE` |
| 所属行业 | ① key 含 `SW_INDUSTRY`（三级全路径，排除更精准）；② key 含 `INDUSTRY`（二级短名） |
| 总市值 | ① key 含 `TOAL_MARKET_VALUE`；② key 含 `总市值` |
| 市盈率 | ① key 含 `PETTM`；② key 含 `市盈率` |
| 市净率 | ① key 含 `PB<` 或 `_PB_`；② key 含 `市净率` |
| ROE | ① key 含 `ROE_WEIGHT`；② key 含 `ROE` 或 `净资产收益率` |
| 营收同比增速 | ① key 含 `营业收入最新同比增长率` |
| 净利同比增速 | ① key 含 `归属母公司股东的净利润最新同比增长率` |
| 毛利率 | ① key 含 `XSMLL` |
| 研发费用占比 | ① key 含 `RDRATIO`；② key 含 `RSEXPENSE_RATIO` |

**为什么用模糊匹配**: API 返回的 key 名在同一字段上会随查询组合变化（如加/不加行业关键词时 key 不同），精确匹配会导致字段匹配失败。

### 2.1.1 季度数据兼容规则

若 NP/OCF 使用 `#LATEST#`，脚本根据归母净利润字段值中的报告期标注识别周期：

| 数据周期 | 净利润硬门槛 | OCF/NP 硬门槛 |
|---------|-------------|---------------|
| Q1（一季报） | 500万元 | > 0 |
| H1（中报/半年报） | 2000万元 | > 0.10 |
| Q3（三季报） | 3500万元 | > 0.30 |
| annual（年报） | 5000万元 | > 0.50 |
| unknown（未知） | 5000万元 | > 0.50 |

这样做是为了兼容接口最新字段返回季度数据的情况，避免把 Q1 利润直接用全年 5000 万硬门槛误杀，也避免跨周期比较现金流和净利润。

### 2.2 数值解析规则

API 返回的值为字符串，带单位后缀时需解析：

```
"2.18亿"     → 218000000       （去掉"亿" × 10^8）
"5000万"     → 50000000        （去掉"万" × 10^4）
"41.40"      → 41.40           （百分比/小数直接 parse）
"2020-10-28" → Date 对象       （上市日期）
```

**管道符处理**: 值中 `|` 后的内容（如报告期标注）丢弃，只取 `|` 前部分。

### 2.3 半导体高增长判定（前置）

在进入过滤条件前，先判定该票是否适用半导体高增长豁免：

```
is_semi  = 行业字段.includes("半导体")
rev_g    = parseNum(营收同比增速)
semi_relax = is_semi && rev_g > 25
```

`semi_relax = true` 时，条件 B（OCF/NP）**豁免不做**，条件 E（毛利率）使用 **半导体放宽阈值 15%** 替代通用阈值 20%。

### 2.4 过滤条件（按顺序执行，不满足即剔除）

**条件 0 — 总市值 ≥ 50亿**
```
mcap = parseNum(总市值)
if mcap 缺失 → 剔除
if mcap < 5,000,000,000 → 剔除
```
阶段一查询已不拉取 50 亿以下分段；脚本仍做兜底硬过滤，防止旧缓存或异常数据混入。

**条件 A — 上市时长 ≥ 1年**
```
list_date = parseDate(上市日期)
if (今天 - list_date) 天数 < 365 → 剔除
```
若上市日期字段缺失 → **保留**（宁可漏过不可误杀）。

**条件 B — 经营现金流 / 净利润 > 0.5**（semi_relax 豁免）
```
if semi_relax → 跳过本条
ocf = parseNum(经营现金流)
np  = parseNum(归母净利润)
period = detectPeriod(归母净利润原始值)

if np <= 0    → 剔除（亏损企业不参与比值）
if ocf / np <= OCF_NP_THRESHOLD[period] → 剔除
if 任一字段缺失 → 保留
```

**条件 C — 归母净利润达到周期感知门槛**
```
np = parseNum(归母净利润)
period = detectPeriod(归母净利润原始值)
if np < NP_MIN_BY_PERIOD[period] → 剔除
if 字段缺失 → 保留
```

**条件 D — 资产负债率 < 70%**
```
debt = parseNum(资产负债率)
if debt >= 70 → 剔除
if 字段缺失 → 保留
```

**条件 E — 毛利率分档检查（阶段二自算）**
```
gm = parseNum(毛利率)

if semi_relax:
    if gm < 15 → 剔除（"毛利率<15%(半导体高增长)"）
else:
    if gm < 20 → 剔除（"毛利率<20%(非半导体)"）

if 字段缺失 → 保留
```

> 背景：阶段一 API 毛利率门槛已从 20% 降到 15%，因此阶段二补回分档检查，确保非半导体维持 20% 硬底线。

### 2.5 输出
打印各条件剔除计数，输出通过列表。

### 2.6 软标签与质量评分（不剔除）

通过硬过滤后的股票额外打软标签，帮助后续模型二和人工复核识别风险。软标签只影响 `质量评分`，不直接剔除。

| 标签 | 触发条件 | 含义 |
|------|----------|------|
| `MID_SMALL_CAP_50_100` | 50亿 ≤ 总市值 < 100亿 | 市值刚过硬门槛，流动性和波动风险更高 |
| `DATA_PERIOD_QUARTERLY` | NP/OCF 使用 Q1/H1/Q3 数据 | 财务数据未覆盖全年，结论置信度下降 |
| `LOW_ROE` | ROE < 5% | 资产回报偏弱 |
| `WEAK_ROE` | 5% ≤ ROE < 10% | 资产回报一般 |
| `WEAK_CASHFLOW` | OCF/NP < 0.5 | 现金流质量偏弱，但因季度阈值或豁免未硬剔除 |
| `HIGH_DEBT_EDGE` | 60% ≤ 资产负债率 < 70% | 接近负债率硬门槛 |
| `NEGATIVE_PE_TTM` | PE_TTM ≤ 0 | TTM 利润口径可能异常或亏损 |
| `HIGH_VALUATION` | PE_TTM > 100 或 PB > 10 | 静态估值偏高 |
| `LOW_BASE_REBOUND` | 净利增速 > 100% 且 ROE < 5% 或净利润低于年报基准 | 低基数反弹风险 |
| `SEMI_CASHFLOW_RELAX` | 半导体高增长现金流豁免生效 | 行业周期/扩产导致现金流暂不硬杀 |
| `MISSING_KEY_DATA` | 关键字段缺失 | 数据完整性不足 |

质量评分以 100 分为基准，按标签扣分，最低 0 分。该分数用于排序和复核，不作为模型一硬门槛。

## 阶段三：行业排除

### 目标
基于阶段一已返回的行业字段，剔除不相关行业。

### 执行方式
直接遍历阶段二通过列表，检查每条记录的行业字段是否命中排除列表。**不额外调 API**。

### 排除行业关键词

以下关键词命中任一条即剔除（用 `includes` 部分匹配）：

```
银行、保险、证券、多元金融、
白酒、食品饮料、服装家纺、家用电器、旅游零售、农林牧渔、商业物业经营、
房地产开发、房地产服务、水泥、建筑装饰、
煤炭、钢铁、石油石化、航运港口、航空机场、
燃气、水务、环保、
医药生物
```

### 匹配规则
`行业字段字符串.includes(关键词)` — 部分匹配即可。例如行业返回 `环保-环境治理-固废治理`，包含 `环保` 即命中剔除。

**行业字段选择**: 优先使用 `SW_INDUSTRY`（东财三级全路径，如 `环保-环境治理-固废治理`），因为排除关键词（如"环保"）能直接命中三级路径中的一级分类。若使用 `INDUSTRY`（东财二级短名，如 `环境治理`），排除关键词无法命中，会导致漏网。

**不在排除列表中的行业，一律保留。**

### 输出
打印剔除的行业分布，输出最终入池股票列表。

## 阶段四：输出 CSV

### 路径
`pool/pool_<YYMMDD>.csv`（取当前日期，如 `pool_260518.csv`）

若 `pool` 目录不存在则先创建。

### 数值规范（所有数值字段统一遵守）

- **纯数值，不含中文单位**：API 返回的 `"17.04亿"` 必须解析为 `1704000000.00`，`"5000万"` → `50000000.00`
- **小数位数**：一律保留 2 位，四舍五入
- **不加千分位逗号**、不加货币符号、不加百分号
- **空值**：字段缺失写空字符串 `""`，不写 `N/A` 或 `0`
- **编码**：UTF-8 with BOM
- **分隔符**：逗号


### 数值解析伪代码

```python
def parse_num(v: str) -> float | None:
    """'17.04亿' → 1704000000.0, '5000万' → 50000000.0"""
    s = v.split("|")[0].strip().replace(",", "")
    if "亿" in s: return float(s.replace("亿", "")) * 1e8
    if "万" in s: return float(s.replace("万", "")) * 1e4
    if "元" in s: return float(s.replace("元", ""))
    return float(s)

def format_num(v: float | None) -> str:
    """1704000000.0 → '1704000000.00'"""
    if v is None: return ""
    return f"{v:.2f}"
```

## 阶段五：打印摘要

执行完成后在终端输出：

1. **各阶段计数**:
   ```
   阶段一: API 拉取 X 只（理论总数 Y，覆盖率 Z%）
   阶段二: 通过 A 只
     - 总市值<50亿: A0 只
     - 总市值缺失: A1 只
     - OCF/NP不达标: B 只
     - 负债率过高: C 只
     - 净利<5000万: D 只
     - 上市不足1年: E 只
     - 毛利率<20%(非半导体): F 只
     - 毛利率<15%(半导体高增长): G 只
   阶段三: 行业排除 H 只 → 最终入池 I 只
   ```

2. **行业分布**: 最终入池股票按行业分组，打印 Top 10（行业名 + 数量）

3. **核心指标均值**（基于 CSV 对应列计算）: `毛利率_pct` 均值、`营收同比增速_pct` 均值、`研发费用占比_pct` 均值、`ROE_pct` 均值、`质量评分` 均值

4. **软标签分布**: 基于 `风险标签` 统计 Top 10，用于判断候选池主要风险来源

5. **截断警告**: 若任一分段触发子分段且仍覆盖不全，打印 `⚠️ 截断警告：段X 实际返回 Y，理论总数 Z`

## 附录：历史踩坑记录

| # | 问题 | 现象 | 正确做法 |
|---|------|------|---------|
| 1 | 行业列缺失 | 查询字符串不含行业触发词时，API 不返回行业字段 | 查询中必须写「查询所属行业」或「按行业分类」 |
| 2 | 数据口径漂移 | 去掉年份前缀后，归母净利润从年报值跌到单季度值，候选池大幅缩水 | 原始字段请求保留年份后缀（如 `2025年年报`） |
| 3 | 毛利率字段缺失 | 部分标的（如润泽科技 300442）缺失 `2025年销售毛利率` 字段，被 API 条件误排除 | 毛利率过滤不加年份前缀，让 API 自动取最新可用值 |
| 4 | API 200 条截断 | 全市场初筛 total=549，单次仅返回 200 | 市值分段互斥查询 |
| 5 | 字段 key 动态变化 | 同一数据字段在不同查询组合下 key 名不同 | 用 includes/contains 模糊匹配，禁用精确 key |
| 6 | 白名单漏标的 | 润泽科技东财分类为"通信服务"不在预设白名单，正确标的被排除 | 全市场初筛 + 行业黑名单 |
| 7 | LATEST 陷阱 | `#LATEST#` 可能是季度数据，若 NP 和 OCF 跨周期比较会导致 OCF/NP 失真 | 优先统一使用年报；年报不完整时 NP/OCF 必须一起降级到 `#LATEST#`，并按 Q1/H1/Q3/年报使用周期感知阈值 |
| 8 | 行业字段选错 | 使用 `INDUSTRY`（东财二级短名如"环境治理"）导致"环保"类 8 只标未被排除 | 优先用 `SW_INDUSTRY`（三级全路径如"环保-环境治理-固废治理"） |
