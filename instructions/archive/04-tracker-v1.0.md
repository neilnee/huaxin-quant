# 模型四：择时跟踪与交易信号模型（自执行指令）

- **版本**: v1.0（发布版，只读）
- **日期**: 2026-05-20
- **核心目标**: 每日收盘后扫描核心跟踪池，结合模型三估值锚点和实时量价关系，为每只标的输出独立的信号分析报告。维护核心跟踪池的调入调出，管理仓位状态。
- **核心哲学**: 价格到位 + 技术共振 = 交易信号。盘后复盘 + 前瞻预警 = 为明天做好准备。支撑止损保护本金，均线止盈保护利润。估值模型可能有盲区，价格偏离时触发复核而非盲从。
- **输入**:
  - `quant/` 目录下最新日期的 `quant_<YYMMDD>.csv`（模型二精选池，取文件名日期最新的那份）
  - `reports/_ranking.csv`（模型三估值锚点数据）
  - `reports/_index.csv`（模型三研究状态追踪）
  - `core_pool.csv`（核心跟踪池，不存在则初始化）
  - `positions.csv`（持仓记录，不存在则创建空模板）
- **输出**:
  - `signals/signals_<YYMMDD>.md`（每日个股信号详细报告）
  - `core_pool.csv`（更新后的核心跟踪池）
  - `positions.csv`（更新后的持仓记录，如有变动）
- **配套脚本**: `scripts/tracker.py`（负责数据拉取、缓存管理、技术指标计算、信号条件预检；LLM 负责信号解读、仓位分析、操作建议措辞和报告撰写）

---

## 总览

每日收盘后运行，分六个阶段：

```
阶段零（池子维护）→ 阶段一（数据拉取）→ 阶段二（信号扫描）
→ 阶段三（前瞻预警）→ 阶段四（估值复核）→ 阶段五（交互确认与输出）
```

**核心设计原则**:
- **脚本算数值，LLM 做判断**：日线拉取、技术指标计算、信号条件预检由 `tracker.py` 固化；信号解读、仓位分析、操作建议措辞、前瞻预警和报告撰写由 LLM 完成
- 持仓数据由你手动维护，模型四每次运行时列出当前记录跟你确认（你始终在场，不存在无人值守场景）
- 支撑止损看买入逻辑是否被破坏，均线止盈看趋势是否转折
- 量价关系贯穿所有信号：缩量放宽容忍度，放量收紧触发条件
- 仓位越重，止盈止损线越紧
- 前瞻预警不执行交易，只提醒明天盘中关注
- 输出以个股为维度，每只标的生成独立的信号分析区块
- 估值锚点信息从 `reports/_ranking.csv` 结构化读取，不解析报告 markdown

## 阶段零：池子维护

### 目标
更新核心跟踪池，确认仓位状态。

### 关键文件结构

**core_pool.csv**（不存在时创建）：

```
code,name,first_added,last_quant_date,consecutive_miss,priority,has_valuation,status
```

| 字段 | 说明 | 示例 |
|------|------|------|
| code | 股票代码 | `="300442"` |
| name | 股票名称 | 润泽科技 |
| first_added | 首次调入日期 | 2026-05-20 |
| last_quant_date | 最近一次出现在模型二精选池的日期 | 2026-05-19 |
| consecutive_miss | 连续未在最新 quant 中出现的次数 | 0 |
| priority | 优先级标记 | `优先` / `正常` |
| has_valuation | 估值报告是否已完成 | TRUE / FALSE |
| status | 跟踪状态 | `跟踪中` / `观察中` / `已移出` / `ETF跟踪` |

**ETF 跟踪说明**：ETF 不经过模型一/二/三（无财报、无量价形态分类、无估值模型），因此：
- `has_valuation` 填 `N/A`
- `status` 填 `ETF跟踪`
- 信号扫描仅适用：S0-硬止损、S4-均线破位、S2-移动止盈（部分适用，ETF 无量价逻辑中的"主力行为"概念，仅看趋势）
- 其余信号（B1/B2/S1/S3/S5/W3）全部跳过
- 前瞻预警：仅适用 W1（价格预警）和 W2（量价预警）
- 估值复核全部跳过

**positions.csv**（不存在时创建空模板）：

```
code,name,asset_type,target_type,target_value,actual_shares,cost_price,stop_loss_override
```

| 字段 | 说明 | 示例 |
|------|------|------|
| code | 股票代码 | `="300442"` |
| name | 股票名称 | 润泽科技 |
| asset_type | 资产类型 | `个股` / `ETF` |
| target_type | 目标计量方式 | `shares`（按股数）/ `amount`（按金额元） |
| target_value | 目标值 | shares→股数（如 1000）；amount→金额元（如 60000） |
| actual_shares | 实际持仓股数 | 500 |
| cost_price | 持仓成本价（元） | 3.048 |
| stop_loss_override | 个人止损比例覆盖（空=用默认值） | -0.15 |

仓位状态判定规则：
- **目标类型为 shares**（个股，按股数管理）：
  - 未持仓：actual_shares = 0
  - 轻仓：actual_shares ≤ target_value × 50%（5 成及以下）
  - 标准仓：actual_shares 超过 target_value 的 50%，不足 75%
  - 重仓：actual_shares ≥ target_value × 75%
- **目标类型为 amount**（ETF，按金额管理）：
  - 未持仓：actual_shares = 0
  - 轻仓：actual_shares × 最新价 ≤ target_value × 50%（5 成及以下）
  - 标准仓：actual_shares × 最新价 超过 target_value 的 50%，不足 75%
  - 重仓：actual_shares × 最新价 ≥ target_value × 75%

### 执行步骤

**0.1 读取输入**
- 读取 `quant/` 目录下文件名日期最新的那份 `quant_<YYMMDD>.csv`
- 读取 `core_pool.csv`（不存在则按上述结构创建空文件）
- 读取 `reports/_ranking.csv` 和 `reports/_index.csv`
- 读取 `positions.csv`（不存在则按上述结构创建空模板）

如果最新 quant 文件的日期距今超过 5 天，打印提醒："模型二精选池已超过 5 天未更新，建议先运行模型二获取最新精选池。"

**0.2 调入判断**

对最新 quant 精选池中的每只标的：

| 场景 | 条件 | 动作 |
|------|------|------|
| 首次调入 | 标的不在 core_pool 中 | 加入 core_pool，first_added=今日，consecutive_miss=0，priority=正常 |
| 加速调入 | 量比 > 2.0（从 quant CSV 的"量比"列读取） | 加入 core_pool，priority=优先 |
| 已跟踪标的 | 标的已在 core_pool 中 | consecutive_miss 重置为 0，更新 last_quant_date |
| 已有估值 | has_valuation=TRUE | 正常跟踪 |
| 缺少估值 | has_valuation=FALSE | 不中断流程，在阶段五终末摘要中统一列出 |

**0.3 调出判断**

对 core_pool 中的每只标的：

| 场景 | 条件 | 动作 |
|------|------|------|
| 持仓保留 | actual_shares > 0 | 无论是否入选最新 quant，永久保留 |
| 观察中 | actual_shares = 0 + consecutive_miss < 5 | 保留，status=观察中 |
| 自然淘汰 | actual_shares = 0 + consecutive_miss ≥ 5 + has_valuation=FALSE | 移出 core_pool，status=已移出 |
| 估值保护 | actual_shares = 0 + consecutive_miss ≥ 5 + has_valuation=TRUE | 保留，status=观察中，标注"有估值，保留跟踪" |

对于本次不在最新 quant 中且 actual_shares = 0 的标的，consecutive_miss += 1。

**0.4 交互确认**

打印当前持仓记录并等待你确认：

```
📋 当前持仓记录（基于 positions.csv）：

| 代码 | 名称 | 目标仓位 | 实际持仓 | 成本价 | 仓位状态 |
|------|------|----------|----------|--------|----------|
| ... | ... | x% | x股 | x元 | ... |

本次调入: <列表>
本次调出: <列表>
缺少估值: <列表>（将在阶段五统一提醒）

请确认以上信息是否准确，如有变动请告知（加仓/减仓/新增/清仓/成本调整/总资金变动）。
确认后继续信号扫描。
```

你确认后，更新 `core_pool.csv` 和 `positions.csv`，进入阶段一。

## 阶段一：数据拉取

### 目标
由 `tracker.py` 拉取核心池所有标的的近60个交易日日线数据，计算技术指标，输出结构化的指标快照供 LLM 在阶段二中引用。

### 执行方式

```bash
python3 scripts/tracker.py                           # 默认：读取 core_pool.csv，拉取全部标的
python3 scripts/tracker.py --test                    # 测试模式：只跑前 3 只
python3 scripts/tracker.py --code 300442             # 单只更新
python3 scripts/tracker.py --no-cache                # 强制跳过缓存，重新拉取
```

### 脚本职责

**1.1 日线数据拉取**
- 从 `core_pool.csv` 读取标的列表
- 复用 `quant_filter.py` 的 API 调用逻辑（直调 `mkapi2.dfcfs.com`，取 `rawTable`，RateLimiter 限流）
- 日线数据本地缓存 `cache/daily/<code>_<YYMMDD>.pkl`，与模型二共用缓存层
- 核心池约 15-25 只，全缓存命中时零 API 消耗

**1.2 技术指标计算**

| 指标 | 计算方式 | 用途 |
|------|---------|------|
| MA5 / MA10 / MA20 | 近 N 日收盘价均值 | 均线止盈 / 破位判断 |
| MA20 斜率 | 近 5 日 MA20 值做线性回归，斜率 ÷ 当前 MA20 × 100% | S4 均线走平判断 |
| 量比 | 当日成交量 ÷ 前 5 日均量 | 放量 / 缩量判别 |
| 缩量程度 | 近 5 日均量 ÷ 近 20 日均量 | 缩量回调 / 量价背离 |
| 近 5 日涨幅 | (今日收盘 - 5 日前收盘) ÷ 5 日前收盘 × 100% | 加速赶顶判断 |
| 近 20 日最高价 | 近 20 日最高价的最大值 | 箱体上沿参考 |
| 近 20 日最低价 | 近 20 日最低价的最小值 | 箱体下沿 / 支撑参考 |

**1.3 箱体形态检测（B2 输入）**

检测价格是否处于箱体盘整并尝试突破：

- 近 20 日价格区间 = 近 20 日最高价 - 近 20 日最低价
- 区间收窄度 = 近 20 日价格区间 ÷ 近 20 日均价
- 箱体盘整：区间收窄度 < 15%
- 突破信号：今日收盘价 ≥ 近 20 日最高价 × 98%（接近或突破上沿）

输出布尔标记：`box_consolidation`（是否箱体盘整）、`box_breakout`（是否突破上沿）。

**1.4 估值锚点加载**

从 `reports/_ranking.csv` 读取每只标的的估值数据。脚本提取以下字段供阶段二引用：

| _ranking.csv 字段 | 模型四用途 |
|-------------------|-----------|
| 下行风险价_元 | S0 支撑位底线 |
| 保守估值_元 | B1/B2 价格区间下沿 |
| 基准估值_元 | B1 价格区间上沿 |
| 乐观估值_元 | B2 价格区间上沿、S1 估值卖点基准 |
| 安全边际折扣率 | 跨标的优先级参考 |

四层价格锚点（下行风险价 / 保守 / 基准 / 乐观）均直接读取，无需近似估算。如某标的无估值报告，该行所有估值字段为空，B1/B2/S1 信号自动跳过。

**1.5 信号条件预检**

脚本对每只标的逐条检查买入/卖出信号的条件，输出触发了哪些信号、关键数值是多少。LLM 不再做数值计算，只做解读和操作建议。

### 预期输出（脚本 stdout）

每只标的输出一个 JSON 行或终端可读的指标摘要，包含：
- 所有技术指标最新值
- 估值锚点（如可用）
- 各信号条件命中情况（命中 / 未命中，及关键阈值对比）
- 箱体检测结果

## 阶段二：信号扫描

### 目标
基于 `tracker.py` 输出的指标快照和信号预检结果，逐只解读买入/卖出信号，结合量价关系和仓位状态输出操作建议。

**重要**：非持仓标的仅展示买入信号（B1/B2），不展示卖出信号。

### 2.1 买入信号

**B1 — 估值区间缩量回调**

| 条件 | 规则 | 数据来源 |
|------|------|----------|
| 价格区间 | 当前股价在保守估值与基准估值之间 | _ranking.csv（直接读取） |
| 缩量回调 | 缩量程度 < 0.8 | tracker.py 计算 |
| 均线支撑 | 距 MA20 在 -5% ~ +3%，或距 MA60 在 -5% ~ +3% | tracker.py 计算 |

三个条件全部满足才触发。条件中的估值部分如该标的无估值报告则跳过，B1 不触发。

| 仓位状态 | 操作建议 | 类型 |
|----------|----------|------|
| 未持仓 | 建议建仓至轻仓 | 执行 |
| 轻仓 | 建议加仓至标准仓 | 执行 |
| 标准仓 | 持有观察，不加仓 | 注意 |
| 重仓 | 不加仓 | — |

**B2 — 箱体放量突破**

| 条件 | 规则 | 数据来源 |
|------|------|----------|
| 价格区间 | 当前股价在保守估值与乐观估值之间 | _ranking.csv（直接读取） |
| 箱体突破 | 箱体盘整 + 今日收盘突破上沿 | tracker.py 计算（1.3） |
| 放量 | 量比 > 1.5 | tracker.py 计算 |

三个条件全部满足才触发。估值条件缺失时跳过。

| 仓位状态 | 操作建议 | 类型 |
|----------|----------|------|
| 未持仓 | 建议建仓至轻仓 | 执行 |
| 轻仓 | 建议加仓至标准仓 | 执行 |
| 标准仓 | 持有观察（量比 > 2.0 可加一次仓） | 注意（或执行） |
| 重仓 | 不加仓 | — |

### 2.2 卖出信号

**优先级总览**：

| 优先级 | 信号 | 核心逻辑 |
|--------|------|----------|
| 最高 | S0-支撑止损 | 买入逻辑被破坏 |
| 最高 | S0-硬止损 | 成本线失守，兜底 |
| 最高 | S1-估值卖点 | 价格透支，减半仓 + 触发估值复核 |
| 高 | S5-加速赶顶 | 情绪极端 |
| 中 | S4-均线破位 | 趋势转折（覆盖 S2） |
| 低 | S3-量价背离 | 动能衰竭，早期预警 |

**S2 与 S4 的关系**：S4 覆盖 S2。当均线走平或向下时，只报 S4，不报 S2。S2 仅在均线仍保持上升（MA20 斜率 > 0.1%/天）但股价短暂跌破时触发。

---

**S0-支撑止损**

触发条件：收盘价 < 关键支撑位 × (1 - 容忍度)

支撑位定义：
- 取近 20 日最低价作为当前支撑参考
- 如已有模型三估值，支撑位不低于保守估值 × 0.8
- 如有持仓成本，取 `max(近20日最低价, 保守估值×0.8)` 作为最终支撑位

| 仓位状态 | 容忍度 | 量价判别 | 操作建议 | 类型 |
|----------|--------|----------|----------|------|
| 轻仓 | 5% | 缩量跌破→5%；放量跌破→3% | 减仓或关注 | 缩量注意 / 放量执行 |
| 标准仓 | 3% | 缩量→等次日确认；放量→即时触发 | 减仓至轻仓 | 缩量注意 / 放量执行 |
| 重仓 | 2% | 无论缩量放量，跌破即触发 | 减仓至标准仓 | 执行 |

---

**S0-硬止损**

触发条件：当前价 < 持仓成本 × (1 + 止损比例)

| 仓位状态 | 止损比例 | 操作建议 | 类型 |
|----------|----------|----------|------|
| 轻仓 | -12% | 建议减仓或清仓 | 执行 |
| 标准仓 | -10% | 建议减仓或清仓 | 执行 |
| 重仓 | -8% | 建议减仓或清仓 | 执行 |

如 `positions.csv` 中 `stop_loss_override` 有值，优先使用个人设置。此信号不看量价，无条件执行。

---

**S1-估值卖点**

触发条件：当前股价 > 模型三乐观估值 × 1.1

| 仓位状态 | 操作建议 | 类型 |
|----------|----------|------|
| 未持仓 | 不买 | — |
| 任何持仓 | 建议减仓至半仓以下 | 执行 |

同时触发估值复核提醒（见阶段四）。如该标的无估值报告，S1 不触发。

---

**S4-均线破位**（覆盖 S2）

触发条件：收盘价 < 止盈均线，且均线走平或向下

均线方向判定（tracker.py 计算）：
- 走平：abs(MA20 斜率) < 0.3%/天
- 向下：MA20 斜率 < -0.2%/天
- 向上：MA20 斜率 > 0.3%/天 → S4 不触发（此时若收盘价跌破均线，触发 S2）

| 仓位状态 | 止盈均线 | 确认要求 | 操作建议 | 类型 |
|----------|----------|----------|----------|------|
| 轻仓 | MA20 | 连续 3 日破位 | 关注，暂不减 | 注意 |
| 标准仓 | MA10 | 连续 2 日破位 | 减至轻仓 | 执行 |
| 重仓 | MA5 | 单日放量破位即触发 | 减至标准仓 | 执行 |

---

**S2-移动止盈**（仅在均线仍向上时触发）

触发条件：收盘价 < 止盈均线 + 均线保持上升 + 当前价 > 成本价 × 1.05

| 仓位状态 | 止盈均线 | 量价判别 | 操作建议 | 类型 |
|----------|----------|----------|----------|------|
| 轻仓 | MA20 | 缩量跌破→等次日；放量跌破→触发 | 关注，暂不减 | 注意 |
| 标准仓 | MA10 | 缩量→等次日；放量→触发 | 减至轻仓 | 执行 |
| 重仓 | MA5 | 无论缩量放量，跌破即触发 | 减至标准仓 | 执行 |

---

**S3-量价背离**

触发条件：近 5 日涨幅超过阈值 + 缩量程度 < 0.6

| 仓位状态 | 涨幅阈值 | 操作建议 | 类型 |
|----------|----------|----------|------|
| 轻仓 | > 5% | 关注，暂不减仓 | 注意 |
| 标准仓 | > 3% | 关注，可减至轻仓 | 注意 |
| 重仓 | > 0%（任何正收益） | 建议减至标准仓 | 执行 |

与缩量调整的区别：缩量调整是股价在均线附近或下方缩量（蓄力），量价背离是股价在均线上方缩量（乏力）。

---

**S5-加速赶顶**

触发条件：近 5 日涨幅 > 20% + 量比 > 2.5

| 仓位状态 | 操作建议 | 类型 |
|----------|----------|------|
| 未持仓 | 不追买 | — |
| 任何持仓 | 建议减仓或清仓 | 执行 |

---

### 2.3 信号叠加处理

本模型定位为"信号雷达"——客观扫描、完整报出，不越权做自动交易决策。最终操作由你在阶段五交互中判断。

当多信号同时触发时：

1. **卖出信号取最高优先级**：S0 > S1 > S5 > S4 > S3。报告只输出优先级最高的卖出信号，次高信号在"其他关注"中简要提及。例如 S1 和 S4 同时触发 → 报 S1（估值卖点优先于均线破位），S4 在脚注提一句"同时跌破 MA，关注趋势变化"。

2. **买卖信号同时触发**：同时报出。典型场景：
   - B1（估值到位）+ S3（量价背离但未恶化）→ 价格到了但还没企稳，你的判断决定是否现在建仓
   - B2（箱体突破）+ S5 临界（近 5 日涨 18%、量比 2.8，接近 S5）→ 突破有效但短期涨幅已大，需你判断追不追

3. **S2/S4 关系**：S4 覆盖 S2。当均线走平或向下时只报 S4。S2 仅在均线仍保持上升趋势时触发。

4. **S0 支撑止损 + S0 硬止损同时触发**：两个都报。操作建议取更紧急的（通常硬止损的减仓幅度更大）。（TODO-3: 后续版本可在此场景引入"最大回撤控制"，定一个最大可接受亏损线，两信号取紧。）

## 阶段三：前瞻预警

### 目标
扫描接近触发但尚未触发的信号，生成"明日关注"清单。

**W1-价格预警**

| 触发条件 | 提醒内容 |
|----------|----------|
| 当前股价距 S0 支撑止损位 < 2% | 明日若继续下跌将触发支撑止损 |
| 当前股价距 S4/S2 止盈均线 < 2% | 明日若跌破均线将触发卖出信号 |
| 近 5 日涨幅 > 15% + 量比 > 2.0 | 若明日早盘继续放量急拉，可能触发 S5 加速赶顶 |

**W2-量价预警**

| 触发条件 | 提醒内容 |
|----------|----------|
| 缩量程度 < 0.5 | 极度缩量，变盘前兆 |
| 近 3 日量比均 < 0.6 | 量能持续萎缩，关注方向选择 |

**W3-催化预警**

| 触发条件 | 提醒内容 |
|----------|----------|
| 模型三催化剂日历中的近期事件，预计触发时间在未来 2 天内 | 明日可能有催化落地，关注开盘反应（需该标的已有估值报告） |

## 阶段四：估值复核

### 目标
检测估值模型是否可能失真，在信号扫描之外独立提醒。

**异常检测条件**：

| 异常类型 | 判断条件 | 提醒内容 |
|----------|----------|----------|
| 价格严重偏离 | 当前股价 < 保守估值×0.7，或 > 乐观估值×1.3 | 估值可能失真，建议人工复核 |
| 报告过期 | `_index.csv` 中"数据截至报告期"距今超过 6 个月 | 估值可能过时，建议重新生成 |
| 一致预期修正 | 最新一致预期与估值报告中偏差 > 30%（当前需手动比对） | 市场预期已重大变化，建议重新估值 |

**S1 触发时的专项复核**：当 S1-估值卖点触发时，附加详细提醒：

```
⚠️ 估值复核提醒：
- 标的：<名称>(<代码>)
- 当前股价：XX.XX 元，已超出乐观估值(XX.XX 元) × 1.1
- 可能原因：模型未充分定价的预期差正在兑现 / 市场情绪驱动 / 估值假设需要调整
- 建议：重新审视模型三估值报告，确认是否需要上调估值中枢
- 是否现在触发模型三重新估值？（确认后执行）
```
