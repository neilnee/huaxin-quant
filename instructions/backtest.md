# 策略买点回测

- **核心目标**：分别检验进入 VCP 页面结构列表的结构轮次，以及前一交易日 Signal Plan 在下一交易日形成的实际买点，在未来 5/10/20 个交易日的价格表现。
- **边界**：不依赖真实买卖，不模拟仓位、止盈止损、滑点或账户收益；结构回测不把每日重复展示当作新样本，买点回测不把形态成熟日和 Plan 发布日当作收益起点，也不统计未成立计划的触发率。
- **输入**：策略数据库中的 Signal Plan、Quant 快照与实际买点事件、共享日线库、`cache/market_regime/market_regime.sqlite` 中买点成立日的完整申万二级板块状态，以及计划日之前已保存到 `cache/capital_flow/capital_data.sqlite` 的个股资金事实；旧文件只作为迁移期兼容回退。
- **输出**：`backtest/backtest_<YYMMDD>.json|md` 及 Dashboard 独立回测数据包。
- **主脚本**：`scripts/backtest.py`。
- **策略配置**：`strategies/backtest.json`。

## 一、开发期规则契约

模型二负责识别 VCP 结构和三类买点，并通过 `setup_plan_inputs` 透出已经计算的价格、量能和失效阈值；Signal Plan 只把这些阈值转换为下一交易日计划。开发或修改相关规则时，必须一次性核对 PULLBACK / BREAKOUT / RETEST、NEW / FOLLOW、常规 / A 类、风险阻断和突破后生命周期的一致性，并用单元测试固化。该核对不是每日工作流步骤，历史回测和日常运行不得每次重复生成一致性审计。

回测与 Dashboard 的“前一交易日 Plan 今日兑现”必须调用同一共享判定，不得各自复制阈值逻辑。Dashboard 可以立即展示尚未走满 5 个交易日的兑现事件；回测收益统计仍只在事件走满相应观察期后纳入成熟样本。

Plan 必须保存来源 Quant 日期、`structure_anchor`、模型二阶段、当日买点和突破后生命周期，以便下一交易日只匹配同一只股票、同一轮 VCP。结构轮次优先使用 `contraction_group` 第一段开始日期；没有该字段时使用收缩段或突破日兼容标识。

## 二、VCP结构入选事件

VCP结构回测以当日 VCP 页面实际展示的 active 列表为准，即 Bloom 状态为 `EARLY / FORMING / MATURE / TRIGGERED / RISK_BLOCKED` 的标的。它验证“结构选取后整体表现”，不要求 Signal Plan 或买点兑现。

同一股票、同一 `structure_anchor` 第一次进入列表的有效交易日形成一条 `VCP_SELECTION` 事件，入选日收盘价为收益基准；周末、节假日或历史误跑日期不得抢占首次事件，连续多日留在列表不得重复计数。股票形成新的结构锚点后可以产生新事件。事件冻结首次入选时的模型二阶段、Bloom 状态、结构分和风险分，后续状态变化不得回写首次入选事实。

结构事件按 5/10/20 个交易日计算持有期总回报，未走满对应周期时留空。VCP结构模块独立提供近30个交易日、近90个交易日、近180个交易日和全部历史四档入选范围，默认近90个交易日；阶段筛选置于左侧、时间范围置于右侧，二者组合决定结构汇总、明细与分页样本。明细中已有5日结果的样本优先，待观察样本统一排后，两组内部均按首次入选日期倒序。它不跟随页面顶部的实际买点成立范围。第一阶段只展示结构总体收益、入选阶段分组和事件明细，不把市场、板块、资金或买点条件加入结构样本筛选，也不据此自动修改结构规则。

## 三、实际买点事件

Plan 发布日为 `D`，只检查下一个有效交易日 `D+1`。Plan 发布本身不是回测事件；只有 `D+1` 收盘后的价格和成交量满足普通触发区、且收盘价未落入失效区时，才形成实际买点事件。

事件分为：

- `NEW`：前一日为允许形成买点的突破前有效 VCP，下一日首次满足 Plan 对应买点的普通条件。Plan 阈值已经来自模型二 `setup_plan_inputs`，运行时不要求模型二在下一日重复输出同名 `setup_signal`；只要求结构轮次一致、VCP 继续有效且未进入失败或过期生命周期。
- `FOLLOW`：前一日已经确认同类型买点，下一日仍满足 Plan 延续条件。它是原买点的次日有效执行窗口，不要求模型二重复输出一个新的首次信号，但下一日必须仍为同一轮有效 VCP，且不得进入失败或过期生命周期。

买点类型固定为 `PULLBACK`、`BREAKOUT`、`RETEST`。同一股票、同一结构轮次、同一买点类型、同一 `NEW/FOLLOW` 只记录第一次实际成立；连续计划不得重复占用样本。`NEW` 与 `FOLLOW` 继续作为事件去重和审计字段，但不作为页面主筛选或策略效果分组；当前研究以买点类型为基础基准。

没有在 `D+1` 成立的 Plan 不形成事件、不记为失败，也不统计触发率。周末、节假日或历史误跑文件不得产生事件。

## 四、常规与 A 类

实际等级互斥：

- `A`：Plan 本身允许 A 类，且 `D+1` 同时满足理想价格区和理想量能条件。
- `REGULAR`：满足普通价格与量能条件，但未完整满足 A 类条件。

突破类普通条件为收盘价位于触发上下限内、成交量不低于普通下限；A 类要求收盘价位于理想区且成交量不低于理想下限。回踩与回踩确认类普通条件为收盘价位于触发上下限内、成交量不高于普通上限；A 类要求收盘价位于理想区且成交量不高于理想上限。所有类型均要求收盘价高于失效价。

满足 A 类的事件只记录一次并标记 `A`，不得同时进入 `REGULAR` 样本。A 类与常规的合计构成全部实际买点。

## 五、收益与滚动窗口

买点成立日 `E=D+1` 的收盘价是唯一收益基准。收益必须采用持有期总回报口径，不能直接用未复权原始收盘价相除：

```text
5日收益  = close(E+5)  / close(E) - 1
10日收益 = close(E+10) / close(E) - 1
20日收益 = close(E+20) / close(E) - 1
```

上式中的期末价值需包含 `E` 之后、目标日及之前发生的公司行为：送股和转增按比例增加持股数，现金分红计入现金收益，配股同时增加股份并扣除配股成本。买点成立日已经完成的除权除息不重复计算。除权数据优先读取覆盖报告日的本地缓存，缺失或缓存日期早于报告日时通过通达信除权除息接口补取；补取失败必须终止当日报告，不得静默退回未复权收益。事件输出需保留期间公司行为明细和收益口径，便于审计。

若持有期跨越除权日，突破判断也使用换算到买点日每股口径的持有价值与冻结 Pivot 比较，不得把除权后的原始股价直接与除权前 Pivot 比较。

以报告日 `T` 为观察截止日：买点年龄不足 5 个交易日时尚未形成任何成熟收益样本；达到 5 日后进入可分析样本。超过 20 日后不得继续计算 20 日之后的价格表现，但已经冻结的 5/10/20 日结果必须继续保留。5 日统计使用所选成立范围内已经走满 5 日的事件，10 日统计使用其中已经走满 10 日的事件，20 日统计使用其中已经走满 20 日的事件；未走完相应周期时留空。停牌时使用不晚于目标交易日的最近有效收盘价。

Dashboard 顶部统一提供“近20个交易日 / 近90个交易日 / 全部历史”三档买点成立范围，默认近90个交易日。交易日范围按买点成立日至报告日的交易日年龄计算并包含边界，例如近20日包含年龄不超过20个交易日的成熟买点。范围切换必须同时作用于总体统计、买点类型、等级、形态成熟度、条件价值和实际买点明细；不得再为统计区与明细区维护不同样本集合。收益观察周期仍固定为5/10/20日，不随成立范围改变。

每个事件继续冻结来源 Plan 的结构枢轴，从买点成立日起最多观察 20 个交易日；首次收盘价达到 `pivot × 1.01` 时记录突破日期、T+N 和相对枢轴涨幅。该字段只是辅助结构证据，不改变收益起点。

### 买点后生命周期

实际买点事件写入 `cache/strategy/strategy_data.sqlite` 后，从买点成立日的下一个交易日开始逐日观察，最长 40 个交易日。参考入场价冻结为买点兑现日收盘价，初始失效价冻结为来源 Plan 的 `invalid_price`，`1R=参考入场价-初始失效价`。逐日保存当前收益与 R 倍数、累计 MFE/MAE、首次触达 1R/2R/3R 的日期、盘中触碰失效价、收盘确认失效、峰值回撤和超时状态。

同一天同时触及目标价和失效价时标记 `AMBIGUOUS`，不得假定先后顺序；收盘确认失效后停止后续观察。生命周期是买入后研究数据，不模拟真实委托、仓位或止盈规则，也不得反向改变 VCP、Signal Plan、买点事件和原有 5/10/20 日收益统计。
历史事件缺少参考入场价或冻结失效价时仍保留事件，并标记 `DATA_INSUFFICIENT`，不得补造风险阈值或从后续行情反推。

## 六、环境、资金和条件价值

市场和板块状态使用买点实际成立日的同日环境，缺失时标记“环境待确认”，不得回退其他日期。板块状态优先读取市场状态库中的完整申万二级日度记录，不能只读取 Dashboard 保存的 Top20。个股所属申万二级行业只是关联同日板块状态的分类元数据：优先使用成立日行业快照；成立日快照缺失时先取不晚于成立日的最近快照，仍无数据时允许使用最早可用快照补建历史归属。输出必须保留行业快照日期与 `point_in_time/prior_snapshot/earliest_available_backfill` 口径，同时保留板块状态自身的 `history_basis`；行业回填不得替换或推导其他日期的板块强弱状态。

个股资金使用 Plan 发布日 `D` 的已缓存事实，观察起点固定为策略配置中的 `capital_observation_start_date`。查询窗口只能以 `D` 为终点，任何 `trade_date>D` 的记录不得进入计算；观察起点之前缓存的历史行只可作为首个正式观察日的状态计算窗口，不能独立冒充当日已经观察到的资金信号。回测不得调用妙想或补取资金，缺失时标记数据不足且保留原买点事件。主力资金与融资资金分别判定，不合成资金总分。

页面和报告先按 `PULLBACK`、`BREAKOUT`、`RETEST` 建立独立买点基准；每个买点类型内部展示实际 `A/REGULAR` 等级和 Plan 发布时的形态成熟度。总体与各买点类型均可评价市场、板块、主力资金和融资资金条件。每个维度只保留“可参与基准”和其中的“强势确认”两级，弱势状态不进入可参与基准，只作为已排除对照：

- 市场可参与基准为趋势扩散、结构行情和修复期；强势确认仅为趋势扩散、结构行情；弱势震荡和防御期作为已排除对照。结构行情的主线集中、快速轮动和结构分化只作为二级说明，不拆成独立回测组。
- 板块可参与基准为持续主线、新晋强化、强势初现、轮动脉冲和高位分歧；强势确认为前三者；观察中、历史积累中和弱势退潮作为已排除对照。
- 主力资金可参与基准为流入或平衡，强势确认为流入，流出作为已排除对照；融资资金可参与基准为加杠杆或稳定，强势确认为加杠杆，去杠杆作为已排除对照。
- 5/10/20 日分别计算强势确认相对可参与基准的样本保留率、胜率提升、平均收益提升、中性组平均收益、赢家遗漏数和赢家遗漏率；未知或数据不足单独计数。
- `样本保留率=强势确认有效样本数/可参与基准有效样本数`。
- `赢家遗漏率=中性组正收益样本数/可参与基准全部正收益样本数`。

胜率定义为对应周期收益大于 0 的样本占比。条件只形成研究证据，不改变实际买点事件、等级、收益或仓位。样本少于配置中的初步观察门槛时标记“样本不足”，达到初步门槛但未达到稳定门槛时标记“初步观察”，达到稳定门槛后标记“稳定性观察”；任何状态均不得自动调参。

Dashboard 所有区域必须使用顶部选中的同一成立范围。页面标明当前范围、成熟样本数量和买点成立日期跨度；资金观察起点之前的样本仍可进入价格、市场和板块统计，但资金条件必须保持数据不足。

## 七、每日工作流

每日 Quant、Signal Plan 和 Market Regime 完成后自动运行：

```bash
python3 scripts/backtest.py --date <YYMMDD>
```

脚本读取已经发布的历史 Plan 和下一交易日事实，发布 `backtest_context_<YYMMDD>.js` 并登记日期索引。每日流程不执行开发期规则一致性审计。
