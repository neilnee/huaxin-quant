# 策略回测（第一版）

- **核心目标**：只检验模型二最终推出的成熟形态和实际买点，在信号首次出现后的 5/10/20 个交易日观察价格表现。
- **边界**：不依赖真实买卖，不模拟仓位、止盈止损或账户收益；不回测 Pool、EARLY、FORMING、评分细项和风险标记。
- **输入**：`cache/quant_runs/quant_<YYMMDD>.json`、共享日线库、信号日市场与申万二级板块状态。
- **输出**：`backtest/backtest_<YYMMDD>.json|md` 及 Dashboard 的独立回测数据包。
- **主脚本**：`scripts/backtest.py`。
- **策略配置**：`strategies/backtest.json`。

## 一、事件口径

只记录两类首次事件：

1. `MATURE_ENTRY`：同一轮 VCP 第一次进入 `VCP_MATURE` 或 `VCP_TIGHT`。
2. `SETUP_TRIGGER`：同一轮 VCP 第一次出现 `PULLBACK_BUY`、`BREAKOUT_BUY` 或 `RETEST_BUY`，并保留具体买点类型。

同一轮结构连续多日保持成熟或买点状态时不重复记录。结构轮次优先使用当前 `contraction_group` 第一段的开始日期标识；旧结构失效、后续形成起点不同的新结构时可产生新事件。

信号基准价固定使用首次事件日收盘价。后续运行只补齐尚未到期的周期结果，不改变事件起点。

每个首次事件同时记录两个突破结果：

1. `突破时间`：冻结事件日模型给出的 `structure_pivot`，从事件日开始逐个交易日检查；首次收盘价达到 `structure_pivot × 1.01` 时，记录突破日期及相对事件日的交易日序号 `T+N`，截至报告日仍未达到则写“无”。观察最多持续到事件后第 20 个交易日。
2. `突破时涨幅`：`首次突破日收盘价 / 首次事件日冻结的 structure_pivot - 1`，表示突破收盘价高出枢轴的幅度。没有突破或枢轴数据不足时留空。

突破判定和涨幅都只使用当时已经产生的日线，枢轴价固定为首次事件日快照，不用后续重算的结构枢轴覆盖。

## 二、滚动窗口

以报告日 `T` 为观察截止日：

- 信号年龄不足 5 个交易日：暂不进入页面回测窗口。
- 信号年龄为 5~20 个交易日：进入当期报告。
- 信号年龄超过 20 个交易日：不再进入当期明细；已完成结果保留在历史日报中。

每个事件按自身信号日 `t0` 计算：

```text
5日收益  = close(t+5)  / close(t0) - 1
10日收益 = close(t+10) / close(t0) - 1
20日收益 = close(t+20) / close(t0) - 1
```

未走完相应周期时字段留空。停牌导致目标日无成交时，使用不晚于目标交易日的最近有效收盘价，等价于停牌期间价格不变。

## 三、环境口径

市场和板块状态只作为分组环境，不改写信号：

- 市场状态使用信号日已确认的 Market Regime 状态。
- 板块状态使用信号日所属申万二级行业的阶段状态。
- 同日环境数据缺失时明确标记“环境待确认”，不得回退到其他日期。

页面按事件类型、信号时市场状态和信号时板块状态汇总各周期的样本数、胜率和平均收益。胜率第一版定义为对应周期收益大于 0 的样本占比。

## 四、每日工作流

每日 Quant 和 Market Regime 完成后自动运行：

```bash
python3 scripts/backtest.py --date <YYMMDD>
```

Dashboard 发布 `backtest_context_<YYMMDD>.js` 并登记日期索引。第一版只形成价格结果基线，不据此自动调参或改变任何上游策略。
