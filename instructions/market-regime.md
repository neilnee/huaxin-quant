# 市场状态与板块热度（Market Regime）

- **核心目标**：基于共享市场数据层，独立计算市场趋势、波动、广度、板块轮动与板块热度。
- **策略边界**：不读取 Pool/Quant/Bloom 输出，不改写模型二 VCP 结构、评分或买点。
- **数据源**：统一 SQLite 日线库；缺口优先通过通达信 TDX/mootdx 补取，失败或未覆盖目标日时以妙想 API 备用源补取。板块成员来自 `tdxhy.cfg + zhb.zip/incon.dat`、`block_zs.dat`、`block_fg.dat`、`block_gn.dat`。
- **策略配置**：`strategies/market-regime.json`。
- **主脚本**：`scripts/market_regime.py`；基础数据由 `scripts/data/market_data_service.py` 管理。

## 运行方式

```bash
# 首次初始化：通过共享数据层创建本地 SQLite，并回填每只全 A 标的近 300 日线
python3 scripts/market_regime.py init --lookback 300

# 盘后增量更新：刷新板块快照、证券母体与最近日线
python3 scripts/market_regime.py update

# 仅读取共享数据库，生成市场状态、板块阶段数据与报告数据
python3 scripts/market_regime.py run

# 跳过 LLM 市场解读，仅使用规则文案兜底
python3 scripts/market_regime.py run --no-llm

# 历史成分快照缺失时显式使用最近完整快照，并标记为非严格点时
python3 scripts/market_regime.py run --date 2026-06-01 --allow-snapshot-fallback

# 批量重算确定性环境时复用已有当日主线，避免重复请求历史资讯和主线 LLM
python3 scripts/market_regime.py run --date 2026-07-01 --no-llm --reuse-existing-mainline

# 检查数据库、覆盖率和最近完整交易日
python3 scripts/market_regime.py status

# 规则升级后的隔离历史回放；先审计，再显式发布
python3 scripts/rebuild_market_history.py
python3 scripts/rebuild_market_history.py --publish

# 直接双击打开本地页面
# dashboard/index.html
```

`init` 支持 `--resume`；初始化中断或局部失败后，不重复请求已完成标的。`--max-codes` 仅用于小样本接口验证，不能产生正式市场状态。

历史规则升级后必须通过 `rebuild_market_history.py` 按交易日顺序回放，不得直接批量覆盖正式状态库。回放默认写入 `.tmp/market_history_refresh/` 的独立状态库并生成差异与哈希审计；只有显式 `--publish` 才更新正式环境派生数据。发布范围仅包括市场状态库、市场确定性指标与板块热度、市场 Dashboard 上下文，以及 VCP/信号页面中的环境字段。现有 Quant、Bloom 输入与状态、Signal Plan、持仓、估值、市场 LLM 解读和每日主线结论必须保持原文件或原字段不变。发布前后必须验证受保护文件哈希一致，并把旧正式状态库与关键环境文件备份到 `.tmp/market_history_backups/`。

历史回放必须保留数据口径：存在同日 universe、板块成分和行业快照时使用 `point_in_time`；早于首个完整快照的日期只能标记 `current_snapshot_backfill/BACKFILL`，不得输出伪装成严格点时的阶段趋势。缺少交易日市场产物的日期不得补造市场状态。

## 数据持久化与输出

```text
cache/market_data/market_data.sqlite
cache/market_data/blocks/<YYMMDD>/

market/sector_heat_<YYMMDD>.csv

```

共享 SQLite 保存原始日线、证券母体、日度母体成员、板块快照和任务日志；市场状态库额外保存每日板块排名、广度、量能与相对强度，作为阶段判断依据。`market/` 保存某日计算结果与供页面读取的 JSON；三者均为本地运行数据，不提交 Git。市场模块不自行下载或维护基础数据。

`stock_strength` 对每只有效 A 股输出 5/20/60 日全市场 RPS、申万二级行业 RPS、趋势位置、量能状态与强度分；`concept_strength` 为“股票 × 通达信概念”关系表，输出概念热度与概念内 20 日 RPS。RPS 只使用当日收盘前已经完成的横截面收益排名。

## 页面数据与状态

页面位于本地运行目录 `dashboard/`，是全系统统一数据分析入口。市场模块通过 `dashboard/data/index.js` 发布可用日期，并按月将每日独立数据包写入 `dashboard/data/<YYYYMM>/market_context_<YYMMDD>.js`；页面按日历选择日期后才动态加载对应包，避免历史数据累积到单一大文件。`publish-dashboard` 可从已有 `market/data/` 归档重建面板包。页面不得重新计算指标、访问通达信或写入数据库。当前 Markdown 保留为简要归档。

当前历史回放与 Dashboard 市场日期起点为 `2026-05-06`。市场模块重建自身日期索引时必须同时保留 signals、vcp、backtest、valuation 等其他模块已经发布的日期索引，不得覆盖独立模块。

### 今日盘面主线

市场模块在现有市场状态和 20 日板块生命周期之外，独立输出一条“今日盘面主线”。该结果只描述当日资金共同交易的叙事链，不参与市场状态、轮动分、板块 5/20 日排名或模型二判断；当日证据不足时必须明确输出“当日无清晰主线”，不得为了每天有标题而强行归纳。

行情层先在申万一级、申万二级和概念题材中计算当日相对强度、上涨扩散、量能活跃度和当日强势股密度，形成候选强势板块；当日强势股密度使用板块内全市场 1 日 RPS 前 10% 成员占比。核心个股按当日 RPS、5 日 RPS、量能和均线位置形成独立的当日强度排序，不复用偏中期趋势的 20 日板块强势股排序。

正常运行时，第一次执行“盘面异动、隔夜消息与盘中验证”检索，并从目标日及此前材料中按出现频次提取少量明确公司或政策实体；第二次按强势股对候选板块的共同覆盖次数排序，优先使用被多只核心股共同覆盖且当日分数高的主题，再结合最高频实体及“原始公告/事件日期”等限定词核验核心催化。不得按板块类型枚举顺序取词，也不得把全部候选和多个泛化实体塞进长查询而稀释共同母题。两次查询按用途和日期分别缓存。多个 AI 细分板块共振时，检索层可补充“AI应用、AI商业化”上位主题词，但不得据此新增行情候选。资讯按发布时间标记为 `pre_open`、`intraday`、`post_close` 或 `unknown`：目标交易日前发布，或目标日 09:30 前明确发布的资讯为盘前证据；目标日 09:30 至 15:00 前为盘中证据；15:00 起为盘后证据。同日标题明确包含复盘、收评、盘后、收官等结果性表述时，不得因错误的 00:00 时间戳被视为盘前证据。发布时间距目标日不超过配置中 4 个自然日的 `pre_open` 资讯可以直接作为核心催化依据；盘中或盘后文章只有在正文明确写出同一窗口内更早的事件日期，并在日期邻近文本中出现核准、公告、披露、发布、财报等可核验事件动作时，才可作为该更早事件的审计载体。此时必须记录 `event_date` 和 `core_timing_basis=reported_prior_event`，核心事件只能概括该明确日期对应的事件，不得概括文章发布后的盘面结果。更早材料只作背景，时间不明且未明确记载更早事件的资讯不得承担核心催化。若没有上述任一合格证据，不得从旧闻或盘后结果倒推启动原因。

LLM 只能从行情候选中选择强势板块和个股，只能从检索结果中提取核心事件，并归纳一条主线名称和“事件 → 预期变化 → 受益环节 → 盘面响应”的叙事逻辑；不得补造板块、个股、事件、数据或因果关系。强势板块和强势个股采用多对多关系，不要求数量相等，但必须双向覆盖：每只入选个股至少属于一个入选板块，每个入选板块也必须至少有一只入选个股作为盘面代表。脚本对两个方向分别执行硬校验，并在最终个股数据中补充其对应的入选板块名称，供日报和页面直接展示。

LLM 选择结果通过上述校验后，脚本可做一次确定性的跨层级产业链补全，不要求 LLM 增加字段：当核心板块全部来自概念层时，只从申万一级/二级行业候选中补充；当核心板块全部来自行业层时，只从概念候选中补充；已经同时包含概念与行业时不再扩展。补充板块必须 `qualified=true`、至少被配置数量的入选核心股共同覆盖，并按覆盖核心股数量、当日强度依次排序；最多补充配置数量且总数不得超过 6 个。补充后必须重新执行板块—个股双向映射。该步骤用于稳定呈现同一叙事链的产业环节，不得加入综合类板块或仅因涨幅高但缺少共同核心股的方向。

LLM 输出仍保持扁平的固定七字段 JSON，不增加事件嵌套结构。`evidence_titles` 第一条必须满足 `core_eligible=true`，`core_event` 只能概括该条证据中由 `core_timing_basis` 指定的盘前已知事件；其余证据可以来自盘中强化或盘后验证。脚本必须校验第一条证据的时间角色。资讯不可用、缺少可审计盘前催化、LLM 失败或证据不一致时，保留行情候选并明确降级原因，不得由模型常识补写催化。

主线名称采用“共同母题 + 当日交易焦点”的受控表达，名称下必须同时展示核心事件、叙事逻辑、强势板块、强势个股和资讯标题依据。每天只输出一条主线，不开发并列的次主线；多个方向竞争且无法形成明确共识时输出无清晰主线。

“板块相对强度排名”支持 `20日` 与 `5日` 两种视图切换；两者均按日期展示当日 Top20，横轴为名次、纵轴为日期、单元格为板块名称。

页面的板块排名以类别内 **20 日相对强度** 为主，5 日相对强度和排名变化用于观察强化或转弱。相对强度采用板块成员等权收益中位数减全 A 等权收益中位数；20 日中位收益、广度、量能、连续上榜天数只用于解释状态，不替代主排名。

## 市场状态展示与确认

页面只展示一个已确认的“当前市场状态”和其持续交易日数。状态卡下方仅在原始判定与已确认状态不一致时，展示“潜在变化”及确认进度（例如“修复期信号，第 1/3 个确认日”）；不把候选状态作为第二个并列结论。

状态依据应写为一段市场表现解读，综合宽基趋势、均线结构、广度、波动和近期强弱分化，避免逐条复述阈值。原始指标仍在宽基指数与广度表中完整呈现。数据更新时间、全 A 覆盖率和板块历史口径放在页面右上角的简要元信息中，不占用状态卡。

当前市场状态标题右侧提供灰色斜体下划线“详情”入口；点击后在整个市场状态卡下方展开/收起独立的“状态判定说明”模块。说明区先展示当前状态的实际值（含全 A 上涨占比）与已命中条件，再列出所有市场状态的触发规则、确认天数和含义，并说明趋势、波动、广度、轮动四项分数的计算口径。默认收起；说明仅展示脚本的既有规则和配置，不参与状态计算。

市场整体趋势表以快速识别为目标：仅展示 1/5/20 日收益、阶段位置、趋势微图、近期量能、短期趋势和 14 日平均波动。阶段位置以距 60 日高点的百分比计算：收盘处于 60 日新高时标记“60日新高”，否则标记浅回撤/中度回撤/深度回撤；趋势微图展示最近 20 日的价格、MA20、MA60 三条线，并附上行结构/回调观察/弱势结构标签，直观表现价格相对均线的位置、均线方向和收敛关系；近期量能采用 5 日平均成交量 / 20 日平均成交量，≥1.15x 为活跃、0.90x–1.15x 为常态、<0.90x 为收缩，单日量比仅保留在数据包；短期趋势将 MA20 五日斜率转为上行/走平/下行箭头。表头居中，1/5/20 日收益列使用紧凑宽度。ATR14 在页面中称为“14日平均波动”，以每个宽基自身的波动风险分位标识低/中/高，并附原始百分比。

板块排名主表仅展示 20 日排名、板块、阶段、阶段趋势、20 日相对强度、5 日相对强度，用于快速筛选，宽度应显著小于右侧详情，表头居中。内部主生命周期只允许“转强”“主线”“退潮”三种有方向结论；未形成明确生命周期的 `NONE` 在页面阶段列显示为中性的“观察”，但不得将“观察”写回生命周期字段或用于策略放行。`BUILDING` 显示“数据积累”，`BACKFILL` 显示“回填数据”，不得伪装成观察结论。阶段趋势在阶段确定后计算，以统一的 `+2/+1/0/−1/−2` 表示板块底层强度明显改善、温和改善、变化有限、温和恶化、明显恶化，再按当前阶段翻译为符合语言逻辑的文案。主表、详情和说明页的趋势标签必须同时显示数字等级与阶段文案，例如“+2 蓄势增强”“−1 主线降温”，并使用统一的五档颜色。阶段趋势只作变化提醒，不参与阶段判定、影子等级、兼容状态或 Signal Plan 放行。短线脉冲只作附加标记。右侧详情承担阶段解释：以紧凑四列网格展示排名百分位、相对强度、20 日中位收益、成员数、5 日上涨扩散、今日参与度、量能、MA20/MA60 覆盖、60 日新高、强势股密度；申万一级、申万二级、概念题材和风格特征均在趋势扩散与阶段轨迹之间展示不重复的板块强势股 Top 3，按现有 `strength_score` 排序，并显示分类适用的 RPS、20 日涨幅、均线确认和量能。阶段轨迹默认仅展示最新 10 日，完整历史由下方排名矩阵提供。矩阵应完整展示最近 20 个交易日，不设置纵向滚动截断；矩阵中的任意板块名称可点击，点击后该板块在所有日期的矩阵单元格以同色高亮，再次点击取消高亮。独立广度模块不展示；全 A 广度在市场状态详情中呈现，板块广度在板块详情中呈现。

市场环境页底部必须提供静态“指标与状态说明”，只解释脚本已有口径，不在浏览器重新计算指标：

- 阶段位置使用收盘价相对 60 日最高价的距离：`≥-0.005%` 为“60日新高”，`[-5%, -0.005%)` 为“浅回撤”，`[-15%, -5%)` 为“中度回撤”，低于 `-15%` 为“深度回撤”。
- 近期量能使用 5 日平均成交量 / 20 日平均成交量：`≥1.15x` 为“活跃”，`[0.90x, 1.15x)` 为“常态”，`<0.90x` 为“收缩”。
- 短期趋势使用 MA20 五日斜率，即 `当前 MA20 / 五个交易日前 MA20 - 1`：`≥0.20%` 为“上行”，`≤-0.20%` 为“下行”，中间区间为“走平”。
- 页面所称 14 日平均波动原始值为 `ATR14 / 收盘价`；单日真实波幅取“当日最高价减最低价、当日最高价与昨收差的绝对值、当日最低价与昨收差的绝对值”三者最大值，ATR14 为其 14 日均值。低、中、高标签按 ATR14、10 日实现波动和 10 日振幅三项历史分位的综合波动风险分划分：`<40` 为低、`[40, 75)` 为中、`≥75` 为高。不得将标签误写成 ATR14 原始百分比的固定阈值。
- 板块说明必须先提供独立的五档数字图例，明确等级表示“相对前一交易日的加权变化方向”，不是涨跌幅、绝对强弱分或阶段等级；再按观察、转强、主线、退潮四个阶段分别解释阶段判定，并在每个阶段内部以彩色标签列出五档趋势文案，不得把阶段条件与趋势提醒混在同一组通用说明中。历史不足 5 日时 `data_status=BUILDING`，不能输出生命周期结论。当日上涨成员占比只表示今日参与度，不参与阶段趋势计算。

板块阶段与阶段趋势按固定顺序计算：

1. `sector_phase` 是主生命周期，必须先独立完成：类型内 20 日排名百分位不高于 15%、此前 5 日至少 4 日达到同一门槛时为“主线”；当前达到 15% 门槛、此前 5 日不足 4 日时为“转强”；此前已形成主线生命周期并连续两个交易日跌出 20% 退出门槛时为“退潮”。退潮是有时效的过渡阶段：重新进入前 15% 时按近期持续性回到“转强”或“主线”；进入退潮后若连续 5 个后续交易日仍未回到前 20%，则退潮结束并回到 `NONE`，页面显示中性的“观察”，避免历史退潮无限继承。其余情况同样为 `NONE`。阶段判定不得读取当日 `sector_health`。
2. `sector_health_level` 与 `sector_health_score` 在阶段确定后计算，只描述当前阶段内部的变化方向。比较当前与前一交易日的 20 日排名百分位、5 日排名百分位、5 日相对强度和 5 日上涨扩散；排名下降代表改善，其余指标上升代表改善。每项变化超过配置阈值后记为 `+1/0/−1` 方向票，再按阶段权重求得范围为 `[-1, 1]` 的 `sector_health_score`；它不是收益率或百分制评分。方向分 `≥0.55` 映射 `+2`，`[0.15,0.55)` 映射 `+1`，`(-0.15,0.15)` 映射 `0`，`(-0.55,-0.15]` 映射 `−1`，`≤-0.55` 映射 `−2`。缺失指标从分母剔除，不得用单日上涨占比补齐。`sector_health` 再按当前阶段翻译：观察使用“蓄势增强/温和改善/震荡观察/观察走弱/弱势恶化”；转强使用“转强加速/转强延续/转强停滞/转强受阻/转强失败”；主线使用“扩散增强/主线健康/主线稳定/主线降温/高位分歧”；退潮使用“强力修复/温和修复/弱势企稳/退潮延续/退潮加速”。正值永远表示板块变强，负值永远表示板块变弱。
3. `short_pulse` 是短线标记：类型内 5 日排名百分位不高于 10%、但尚未进入 20 日强势区时为真；它不是主状态。
4. `data_status` 是数据质量：`READY`、`BUILDING` 或 `BACKFILL`。历史不足、非严格点时回填不得伪装成强弱结论。

为兼容尚未迁移的 Signal Plan 和历史回测，过渡期继续输出 `sector_state`，但它只能由阶段映射生成，不读取阶段趋势：主线映射“持续主线”，转强映射“强势初现”，短线脉冲映射“轮动脉冲”，退潮映射“弱势退潮”，其余映射“观察中”，数据未就绪映射“历史积累中”。影子等级同样只读取阶段：主线为 A、转强为 B、其余为 D。新页面和后续新逻辑必须读取分层字段。

状态切换采用非对称滚动窗口确认：转入防御期、弱势震荡或结构行情时，最近 3 个交易日内同一原始状态出现至少 2 次即确认，不要求连续；转入修复期或趋势扩散时，最近 3 个交易日须 3 次均为同一原始状态。首次建立状态历史时，以当日规则判定初始化当前状态。日内风险事实可即时展示，但不得跳过确认机制改写已确认状态。

内部状态按以下优先级判定，广度阈值统一使用四项合成的 `breadth_score`，不得用单日全 A 上涨占比替代：

1. `DEFENSIVE`：`breadth_score ≤ 45`，或波动风险分 ≥ 75 且轮动分 ≥ 65。
2. `OFFENSIVE`：趋势分 ≥ 65、`breadth_score ≥ 60`、波动风险分 ≤ 60。
3. `RECOVERY_WATCH`：至少 3/6 宽基站上 MA20、至多 2/6 站上 MA60、全 A 上涨占比 ≥ 50%。
4. `CONSOLIDATING`：未触发防御期，且波动风险分 ≥ 70、趋势分 < 50、站上 MA20 的宽基不超过 2/6、全 A 上涨占比 ≥ 50%；表示普跌压力缓解，但指数趋势尚未修复。
5. `SELECTIVE`：未触发上述状态的完整覆盖状态，页面主状态统一展示“结构行情”。轮动分 ≥ 60 时附加“快速轮动”，轮动分 < 60且核心类别至少有一条连续主线时附加“主线集中”，其余附加“结构分化”。附加说明不是新的市场状态。

轮动分已经由各类别 Top10 日间平均重合度换算，轮动分 ≥ 60 等价于平均重合度 ≤ 40%，不得再叠加同口径的重合度条件。选择性结构的展示细分不建立第二套内部状态，不改变 `SELECTIVE` 的确认历史。

市场解读和今日盘面主线归纳固定调用策略配置中的 `deepseek-v4-flash`（OpenAI 兼容 Chat Completions）；本地 `.env` 只提供 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`，全局 `DEEPSEEK_MODEL` 不覆盖市场模块。今日主线使用思考模式和充足的总输出预算；只有接口明确返回 `finish_reason=length` 或空正文时，后续重试才切换为非思考模式，固定七字段输出不变。市场解读输入较小且只生成受约束短文，继续使用非思考模式。接口返回长度截断或正文为空时必须记录结束原因、完成 token 和推理 token，不得将其笼统记为 JSON 格式错误。市场解读采用“主结论 → 两至三个关键证据 → 市场结构含义 → 后续观察”的单段结构，不逐一播报指数，不重复状态标签；除非解释明显分化，否则不得列举单个指数。LLM 返回一段纯文本，负责前 3 部分；脚本统一补上最后一句“接下来重点观察”，说明广度、均线或波动确认，不能构成操作建议。正文目标为 90–150 字；单次生成上限为 1,600 tokens，最多重试 4 次。为保留通过事实与完整句校验的简短解读，字数校验下限为 30 字、上限为 220 字。LLM 仅可读取已确认状态、候选变化进度、趋势/波动/广度、轮动分数、宽基指标和全 A 广度，不得调用外部数据、改变状态或分数、编造事实、预测涨跌，亦不得输出具体买卖或仓位建议。未配置、调用失败或格式不合格时必须保留规则文案兜底，并记录 `llm.status`；不得影响市场状态、板块计算和报告生成。

内部市场状态包括 `OFFENSIVE`、`SELECTIVE`、`RECOVERY_WATCH`、`CONSOLIDATING`、`DEFENSIVE`，页面一一展示为“趋势扩散、结构行情、修复期、弱势震荡、防御期”。板块主生命周期只有“转强、主线、退潮”，阶段趋势、短线脉冲和数据质量分别展示。状态必须引用最近阶段的指数、排名、广度和量能证据；阶段趋势不得混入阶段或信号决策。

发布到 `market_context` 的 `market_state` 必须同时提供 `confirmed_state` 与 `candidate_state`：前者是通过多日确认并供下游仓位计算使用的正式状态，后者是当日原始候选，只用于潜在变化提示。下游不得用候选状态提前替代确认状态。

运行时，脚本自动检查最近 20 个交易日的板块阶段指标。缺失日期使用**当前板块成分快照**和已持久化的个股日线做基线回填，输出标记为“当前成分快照回填（非严格点时）”；已存在的每日板块快照及其计算结果不得被该回填覆盖。日报和页面必须展示历史口径，严格点时回测只能使用每日快照积累后的数据。

## 兼容指标

模块输出四个独立分数：

- `trend_score`：六个宽基的 MA20/MA60、MA20 斜率和 20 日收益。
- `volatility_score`：ATR14、10 日实现波动与 10 日振幅；分高代表风险高。
- `breadth_score`：全 A 上涨比例、站上 MA20/MA60 比例与 60 日创新高减创新低比例。
- `rotation_score`：行业、概念、风格、指数成分集合的强势排名重合度与持续性；分高代表轮动快。

状态为 `OFFENSIVE`、`SELECTIVE`、`DEFENSIVE`、`CONSOLIDATING`、`RECOVERY_WATCH`。状态切换需满足配置中的多日确认规则。申万一级、二级、三级行业，概念、风格、指数四类热度分别排名；每类热度由相对强度、成交活跃、上涨扩散、强势股密度和持续性组成。

## 历史边界

个股日线可在初始化时回填；板块成分严格点时可得仅从首次保存每日快照开始。缺少目标日期快照时，默认运行必须报数据未就绪，不得将当前成分伪装为历史成分。仅在历史补录明确传入 `--allow-snapshot-fallback` 时，才可选取距离目标日最近的完整成分快照计算，并在报告元数据和板块历史中标记 `current_snapshot_backfill`（页面显示“当前成分快照回填（非严格点时）”）。该降级结果可用于市场环境观察，不得用于宣称严格点时板块回测。

历史批量重算可组合使用 `--no-llm --reuse-existing-mainline`：市场状态解读使用当次确定性指标的规则文案；若目标日已经保存过 `daily_mainline`，则原样复用，避免重复检索历史资讯。没有已有主线的日期仍输出规则型降级结论，不得借用其他日期的主线。
